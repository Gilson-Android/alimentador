API HTTP do AquaFeeder

Tudo que a interface web faz está exposto como API. Serve para automatizar com n8n, Home Assistant, cron, script ou qualquer coisa que fale HTTP. Sem nuvem, sem conta, sem intermediário — a comunicação é direta com o aparelho na sua rede.

Endereço base

ServiçoPortaExemplo
Interface + API80http://aquafeeder.local
Vídeo MJPEG81http://aquafeeder.local:81/stream

O nome aquafeeder é configurável em Ajustes → Nome na rede. Se o mDNS (.local) não funcionar na sua rede, use o IP direto — e reserve o IP no roteador para ele nunca mudar.

Todas as respostas JSON usam Content-Type: application/json; charset=utf-8 e Cache-Control: no-store.

Autenticação

Sessão por cookie. Faça POST /api/login com a senha da interface; a resposta traz um Set-Cookie: af=<token> válido por 30 dias. Mande esse cookie nas chamadas seguintes.

  • O aparelho guarda até 4 sessões simultâneas (celular, PC, script...).
  • As sessões vivem em memória: reiniciar o aparelho invalida todas.
  • Se a senha da interface estiver vazia, a API responde sem autenticação nenhuma. Cômodo para testar, ruim para deixar assim.
Não exponha isso na internet. É HTTP puro, sem TLS: a senha vai em texto claro pela rede local. Para acesso externo use VPN/Tailscale ou o bot do Telegram.

Gerador de comandos

O -c ck.txt grava o cookie num arquivo e o -b ck.txt o reenvia. Rode o login uma vez e depois use o resto quantas vezes quiser.

Endpoints

POST/api/login público

Cria a sessão. Corpo JSON com a senha da interface.

curl -c ck.txt -X POST http://aquafeeder.local/api/login \
     -d '{"pass":"minhasenha"}'

200 {"ok":true} + header Set-Cookie: af=...
401 {"err":"senha incorreta"}

GET/api/status requer sessão

Estado geral. É o endpoint para monitoramento externo.

{
  "wifi": true,          // conectado como estação
  "ip": "192.168.0.42",
  "rssi": -58,           // dBm; abaixo de -75 é sinal ruim
  "ap": false,           // true = está em modo configuração
  "time": "14:35",       // "sem hora" se o NTP não sincronizou
  "lastFeed": "23/08 08:00",
  "fedToday": 4,         // porções hoje
  "maxPerDay": 10,
  "busy": false,         // motor girando agora
  "total": 812,          // porções desde sempre
  "cam": true,
  "camErr": "",
  "heap": 214532,
  "up": 86400,           // segundos ligado
  "fw": "1.0.0"
}
Alerta útil: se fedToday == 0 depois do horário da primeira refeição, algo está errado. Se time == "sem hora", a agenda não vai disparar.
POST/api/feed?p=N requer sessão

Alimenta N porções (padrão 1). Respeita todas as travas de segurança: máximo por acionamento, limite diário e intervalo mínimo.

curl -b ck.txt -X POST "http://aquafeeder.local/api/feed?p=2"
CódigoCorpoQuando
200{"ok":true}enfileirado (retorna na hora, não espera o motor)
429{"err":"Limite diário atingido (10 porções). Trava de segurança."}estourou o máximo do dia
429{"err":"Aguarde 32s (intervalo mínimo)."}chamou muito rápido
429{"err":"Já existe uma alimentação em andamento."}motor ocupado
429{"err":"Máximo por vez: 4 porções."}N acima do limite
A resposta 200 não garante que a ração caiu — só que o comando foi aceito. Para confirmar de verdade, consulte /api/log depois de uns segundos e olhe ok e pulses (precisa do sensor de grãos).
POST/api/jog?s=N requer sessão

Gira a rosca N passos crus, sem contar no limite diário. Negativo recua. Serve para desentupir e para encher a rosca depois de limpar.

# uma volta para frente (28BYJ = 4096, NEMA 1/8 = 1600)
curl -b ck.txt -X POST "http://aquafeeder.local/api/jog?s=4096"

# meia volta para trás
curl -b ck.txt -X POST "http://aquafeeder.local/api/jog?s=-2048"

Limitado a ±4 voltas por chamada. Avançar joga ração no aquário — cuidado para não usar como forma de alimentar, porque escapa das travas.

Configuração completa e agenda. Não devolve segredos (senha do Wi-Fi, senha da interface e token do Telegram nunca saem).

POST/api/config requer sessão

Gravação parcial: mande só os campos que quer mudar. Salva na memória permanente e aplica na hora.

# mudar só a dose
curl -b ck.txt -X POST http://aquafeeder.local/api/config \
     -d '{"stepsPerPortion":2048}'

# apertar a trava diária antes de viajar
curl -b ck.txt -X POST http://aquafeeder.local/api/config \
     -d '{"maxPerDay":6,"maxPerRequest":2}'

Resposta: {"ok":true,"reboot":false}. O campo reboot vem true quando você mudou Wi-Fi (ssid/pass) ou host — nesse caso o aparelho reinicia sozinho ~1 s depois.

CampoFaixaO que é
stepsPerPortion40–20000passos por porção (a dose)
stepUs1000–8000µs entre passos (velocidade)
reverseboolinverte o sentido de giro
maxPerDay1–60trava diária
maxPerRequest1–20trava por acionamento
minIntervalS0–3600intervalo mínimo entre acionamentos
catchUpMin0–720janela para recuperar horário perdido
sensorEnabledboolsensor de grãos (exige reiniciar)
camSize0–30=320×240 1=640×480 2=800×600 3=1280×720
camQuality10–3010 = melhor imagem, 30 = arquivo menor
camVflip, camHmirrorboolgira / espelha a imagem
tzstringfuso POSIX. Brasil: <-03>3
slotsarray de 8a agenda, ver abaixo
uiPass, pass, tgTokenstringsegredos: só entram, nunca saem
GET/api/log requer sessão

Últimas 24 alimentações, da mais nova para a mais antiga. O histórico vive em memória — reiniciar limpa (o contador do dia e a última refeição, não).

{"items":[
  {"when":"23/08 18:00","p":2,"src":"agenda","pulses":15,"ok":true},
  {"when":"23/08 12:31","p":1,"src":"telegram","pulses":7,"ok":true},
  {"when":"23/08 08:00","p":2,"src":"agenda","pulses":0,"ok":false}
]}
CampoSignificado
srcagenda, manual, telegram, botao ou jog
pulsesgrãos contados pelo sensor (0 se não tem sensor)
okfalse = o sensor não detectou ração nem depois de tentar desentupir
POST/api/reboot requer sessão

Responde {"ok":true} e reinicia ~700 ms depois. Todas as sessões caem.

GET/snapshot.jpg requer sessão

Um JPEG na resolução configurada.

curl -b ck.txt http://aquafeeder.local/snapshot.jpg -o aquario.jpg

503 {"err":"câmera indisponível"} se a câmera não inicializou — veja camErr no status.

GET:81/stream requer sessão

Vídeo MJPEG (multipart/x-mixed-replace), ~10 fps, em porta separada para um cliente de vídeo não travar a API.

<img src="http://aquafeeder.local:81/stream">

O cookie de sessão vale para as duas portas (cookie não distingue porta). Uma conexão de vídeo consome quase toda a banda do Wi-Fi do ESP32 — use foto no dia a dia.

Erros

Erro sempre vem como {"err":"mensagem em português"} com o HTTP correspondente:

CódigoSignificado
400corpo inválido ou parâmetro faltando
401sem sessão ou senha errada — refaça o login
429trava de segurança barrou (é o caso mais comum)
503câmera indisponível
Como as sessões vivem em memória, um script de longa duração deve tratar 401 refazendo o login automaticamente — é o que acontece depois de uma queda de energia.

Formato da agenda

São sempre 8 slots. Mande o array inteiro; os que faltarem viram desabilitados.

{"slots":[
  {"en":true, "h":8,  "m":0,  "dow":127, "p":2},
  {"en":true, "h":18, "m":30, "dow":62,  "p":1},
  {"en":false,"h":0,  "m":0,  "dow":127, "p":1}
]}
CampoFaixaO que é
enboolslot ativo
h / m0–23 / 0–59hora local do aparelho
dow0–127máscara de dias, bit 0 = domingo
p1–20porções nesse horário

Máscara de dias

DiaBitValor
domingo01
segunda12
terça24
quarta38
quinta416
sexta532
sábado664

Todos os dias = 127. Só dias de semana = 2+4+8+16+32 = 62. Só fim de semana = 1+64 = 65.

Integrações

Python — alimentar e checar se caiu

import requests, time

BASE = "http://aquafeeder.local"
s = requests.Session()
s.post(f"{BASE}/api/login", json={"pass": "minhasenha"}, timeout=5)

r = s.post(f"{BASE}/api/feed", params={"p": 1}, timeout=5)
if r.status_code != 200:
    raise SystemExit("barrado: " + r.json()["err"])

time.sleep(8)                                  # espera o motor
ultimo = s.get(f"{BASE}/api/log", timeout=5).json()["items"][0]
print(ultimo)
if not ultimo["ok"]:
    print("ALERTA: nao caiu racao!")

Mais simples ainda: deixe a senha da interface vazia enquanto o alimentador estiver só na LAN e chame o /api/feed direto, sem login. Menos seguro, muito menos nó.

Home Assistant — configuration.yaml

rest_command:
  alimentar_peixes:
    url: "http://aquafeeder.local/api/feed?p=1"
    method: POST
    headers:
      Cookie: "af=SEU_TOKEN_AQUI"

sensor:
  - platform: rest
    name: Aquario porcoes hoje
    resource: "http://aquafeeder.local/api/status"
    headers:
      Cookie: "af=SEU_TOKEN_AQUI"
    value_template: "{{ value_json.fedToday }}"
    json_attributes: ["lastFeed","rssi","busy","cam"]
    scan_interval: 300
Token fixo no YAML só funciona até o aparelho reiniciar. Para algo que nunca quebra, deixe a senha da interface vazia e proteja pela rede (VLAN de IoT, firewall no roteador).

Alerta caseiro: "não alimentou hoje"

#!/bin/bash
# rode no cron as 21h: 0 21 * * * /caminho/checa.sh
B=http://aquafeeder.local
curl -s -c /tmp/ck -X POST $B/api/login -d '{"pass":"minhasenha"}' >/dev/null
N=$(curl -s -b /tmp/ck $B/api/status | grep -o '"fedToday":[0-9]*' | cut -d: -f2)
[ "${N:-0}" -lt 2 ] && echo "AquaFeeder: so $N porcoes hoje!" | mail -s alerta voce@email

CORS e uso pelo navegador

O firmware não envia headers CORS. Isso é de propósito: impede que um site qualquer aberto no seu navegador dispare comandos no alimentador. Consequências:

  • Chamar a API por fetch() de outra origem (inclusive desta página) é bloqueado pelo navegador.
  • A interface própria do alimentador funciona porque é servida pelo mesmo host.
  • O cookie é SameSite=Lax, então nem em requisição de terceiros ele vaza.

Por isso o gerador acima produz comandos para o terminal em vez de executar no navegador. Se você quiser mesmo chamar de uma página externa, adicione o header em firmware/src/webserver.cpp — e entenda que está abrindo mão dessa proteção:

httpd_resp_set_hdr(r, "Access-Control-Allow-Origin", "*");
